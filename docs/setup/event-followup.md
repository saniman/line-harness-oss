# イベント参加者アフターフォローのセットアップ

イベントの**参加者**と**キャンセルした人**に、開催日を起点にした自動メッセージを送るための設定手順。

コード側の実装は `apps/worker/src/services/event-followup.ts`。
配信そのものは既存のシナリオ配信エンジン（`services/step-delivery.ts` / cron）に乗っている。

## 全体像：シナリオを 2 本つくる

| シナリオ | トリガー | 誰に届くか |
|---|---|---|
| 参加者向け（お礼） | **イベント参加・決済時**（`event_booking`） | 申込／決済が確定した人 |
| キャンセル者向け | **イベントキャンセル時**（`event_cancelled`） | 参加確定後にキャンセルした人 |

友だちは同時にどちらか一方にしか入らない。

```
申込・決済が確定 → 参加者向けに登録（キャンセル者向けの登録があれば停止）
        ↓ キャンセル
参加者向けを停止 → キャンセル者向けに登録
        ↓ 再申込
キャンセル者向けを停止 → 参加者向けに登録
```

> **「お礼」と「残念でした」が両方届くことはない**。
> 乗り換えのたびに、反対側の登録を `completed` にしてから登録している。

## 1. 参加者向けシナリオを作る

1. 管理画面 → **シナリオ** → 「新規作成」
2. 名前：`イベント参加者フォロー` など
3. トリガー：**イベント参加・決済時**
4. 作成後、詳細画面でステップを追加する
   - 配信タイミングが「**開催日の N 日後 / 時刻**」の形式になる（通常の「◯日後」ではない）
   - 例：`開催日の 1 日後 10:00` に お礼メッセージ
5. 「有効」にする

## 2. キャンセル者向けシナリオを作る

手順は同じで、トリガーだけ **イベントキャンセル時** を選ぶ。
配信タイミングは参加者向けと同じく **イベント開催日が起点**なので、
「開催日の 1 日後 10:00」にすれば、お礼と同じタイミングで別の文言が届く。

### 推奨文言（開催日 +1 日 / テキスト）

```
{{name}}さん、こんにちは。
今回はご都合が合わず残念でした🌱

またタイミングが合うときにお会いできたらうれしいです。
次回のイベントが決まりましたら、あらためてご案内しますね。
```

**キャンセル者向けでは URL 誘導をしない。**

- 次回イベントが常に用意されているとは限らず、リンク先が空・古い状態だと体験が悪い
- イベント告知は**一斉メール**で行っているため、LINE 側は関係を保つ役割に徹する
- `.claude/rules/line-messaging.md` の「外部リンクは離脱コストを生む／リンク不要」とも一致する

参加者向け（お礼）と違い、**行動を促さない**のがポイント。
キャンセル直後に売り込むと心理的な負担になるため、次の接点を約束するだけにとどめる。

## 3. 動作条件と落とし穴

### 対象は「参加確定後のキャンセル」だけ

`event_bookings.status` が `confirmed`（決済完了 / 当日現金の申込）だった予約を
キャンセルしたときにだけ、キャンセル者向けシナリオへ登録する。

`pending`（Stripe の決済画面まで進んだが支払わずに取り消した）は**対象外**。
申込意思が薄く、誤送信リスクのほうが大きいため。

### 開催日を過ぎてからのキャンセルは登録しない

開催日アンカーは「開催日の N 日後」なので、開催後にキャンセルすると配信予定時刻が
**過去**になり、次の cron で即座に送られてしまう。それを避けるために登録をスキップする。
このとき参加者向けの停止だけは行うので、お礼が誤送信されることはない。

### friend_id が紐付かない予約には届かない

LIFF 外で決済した等で `event_bookings.friend_id` が `null` の予約は、
送る相手を特定できないため参加者向け・キャンセル者向けどちらの対象にもならない。

### 同時に複数のイベントへ申し込むと 2 件目は登録されない

`friend_scenarios` の UNIQUE 制約（`friend_id, scenario_id` / `status != 'completed'`）により、
1 人の友だちが同じシナリオに同時に 2 件登録されることはない。
開催中のイベントを並行して複数走らせる場合は、この制約に注意する。

### シナリオが 1 本も無い場合

キャンセル者向けシナリオを作っていなければ、キャンセルした人には**何も届かない**
（参加者向けの停止だけが行われる）。誤送信は起きないので、まずは参加者向けだけ運用しても問題ない。

## 4. 既存参加者をあとから登録する

イベント詳細画面の「参加者を一括登録」から、確定参加者を任意の
**イベント参加・決済時**シナリオへ開催日アンカーでまとめて登録できる。
キャンセル者の一括登録には対応していない。
